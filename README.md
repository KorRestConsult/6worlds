# Restaurant Academy — Demo

Нейтральный демонстрационный MVP для ресторанов: сотрудник изучает меню кухни и бара, тренируется без влияния на рейтинг, проходит аттестации у управляющего, а управляющий видит подтверждённые знания команды.

## Текущая продуктовая логика

1. Сотрудник изучает карточки кухни и бара.
2. Карточки содержат фото, цену и ключевые факты; для бара дополнительно показаны объём, крепость, вкус, подача и бокал.
3. Тренировки — только обучение. Их результаты **не влияют на рейтинг**.
4. Рейтинг сотрудника формируется **из нескольких аттестаций**.
5. Управляющий работает с доступом и PIN через карточку конкретного сотрудника.
6. Управляющий может добавлять и редактировать сотрудников и видеть историю аттестаций.
7. Управляющий может отправить конкретному сотруднику тренировочный тест; сотрудник проходит его в своём кабинете; результат возвращается управляющему.

## Firebase / Firestore

Restaurant Academy должен использовать **отдельный Firebase project**.

Целевое имя проекта:

```text
restaurant-academy-demo
```

Firebase проекта Slow использовать запрещено — ни его Firestore, ни отдельную коллекцию/документ внутри него, ни Authentication, ни Storage.

До подтверждённого создания отдельного Firebase-проекта приложение продолжает работать локально через `localStorage`. Перенос `employees / assignedTests / testResults` в Firestore не выполняется.

После создания отдельного проекта следующий шаг:

1. зафиксировать точное имя и `projectId` нового Firebase project;
2. подключить его к `KorRestConsult/6worlds`;
3. только затем создать структуру Firestore;
4. мигрировать `employees / assignedTests / testResults`;
5. включить realtime-синхронизацию двух устройств.

## Намеренно отложено

- промышленная модель отдельных коллекций для больших сетей и тысяч сотрудников;
- импорт живого меню;
- AI и интеграции;
- окончательная ролевая авторизация сотрудников вместо демо-переключения ролей.
